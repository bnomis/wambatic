    The GitHub token¶

    What token wambatic needs, how it finds it, and when it needs none.

    wambatic reads GitHub through its API, which answers only requests that identify a user. That identity is a personal access token: a long string you create in your GitHub settings and that acts with the permissions you give it.

    The quickest way¶

    If you use the GitHub CLI and have run gh auth login, there is nothing to do: wambatic asks gh auth token for the token. Otherwise:

    export GITHUB_TOKEN=<token from https://github.com/settings/tokens>

    How the token is found¶

    flowchart TD
    start([wambatic needs to call GitHub]) --> env{GITHUB_TOKEN set<br/>and not empty?}
    env -- yes --> use[Use it]
    env -- no --> gh{gh auth token<br/>prints a token?}
    gh -- yes --> use
    gh -- no --> fail[Stop with an error<br/>naming the fix]

    A report that makes no request, with --no-fetch or a --max-age that the cache already satisfies, needs no token at all.

    A GitHub Enterprise Server¶

    For a host set with --github-host, wambatic never uses GITHUB_TOKEN; it looks for GH_ENTERPRISE_TOKEN, then GITHUB_ENTERPRISE_TOKEN, then gh auth token --hostname <host>. Run gh auth login --hostname <host> once to use the GitHub CLI. See GitHub Enterprise Server.

    What the token may do¶

    wambatic only reads. Create a classic token or a fine-grained one.

    Classic token (GitHub docs):

    Scope Needed for
    public_repo Public repositories; enough for most uses
    repo Private repositories
    read:org Private membership of an organisation

    Fine-grained token (GitHub docs), with read access to:

    • Repository permissions: Metadata, Contents, Pull requests, Issues and Actions
    • Organisation permissions: Members

    A fine-grained token reaches only the repositories you select when you create it.

    What wambatic does with it¶

    • The token is never written to the cache, the logs or a report.
    • A GITHUB_TOKEN that appears in an error message is replaced by ***.
    • The web app uses the token of the environment it runs in and never sends it to the browser.
